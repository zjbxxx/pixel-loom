# 像素织机 · Pixel Loom

把像素搅成噪声，而且随时能逐像素还原。一个纯前端、零依赖的单文件图像置乱工具。

- **在线访问**：<https://pixel-loom.app.workbuddy.host/?sharecode=4S3VJ6EXN5>
- **本地运行**：直接用浏览器打开 `pixel-loom.html`，无需安装、无需构建、无需联网

---

## 它是什么

Pixel Loom 对图片做一次**严格可逆**的像素级置乱：处理后的图片在人眼里就是一片噪声，看不到任何原图轮廓；但只要拿到密钥，就能一个字节不差地还原回原图。

与常见的「马赛克 / 模糊 / 局部涂抹」不同，它不是遮盖，而是**双射变换**——信息没有丢失，只是被重排了。

## 功能

| 能力 | 说明 |
| --- | --- |
| 加密（置乱） | 拖入图片 → 调节强度 → 生成噪声图，输出无损 PNG |
| 还原 | 拖入置乱图，自动读取内嵌密钥并逐像素复原 |
| 打乱强度 | 1%–100% 可调，实时显示预计被改写的像素比例 |
| 口令保护 | 可选设置口令，用 PBKDF2 派生密钥；留空则使用一次性随机密钥 |
| 元数据备份 | `eyJ...` 开头的一串字符，就是写进图里那行标记的副本，**只在像素未变、仅标记被剥离时有用**。有口令时口令才是凭据，这串收成结果区下方的一行灰字链接，按需展开；无口令时才作为「钥匙本身」直接展示。微信压缩、截图、转 JPG 都会改写像素，它救不回来 |
| 可逆性自检 | 生成后自动校验解密结果是否与原图逐字节一致 |
| 指纹校验 | 原图像素的摘要随图保存，还原后再比一次。「口令对但图不对」（传了普通照片、截图副本）会被明确拦下，而不是输出一片噪声还报成功 |
| 单页入口 | 只有一个拖放区，图进来后由两个按钮决定「打乱」还是「还原」，不用先想该进哪个页 |
| 就地展开 | 动作区在入口卡里往下展开，不换页；缩略图与 ✕ 常驻，展开状态下也能直接换图 |
| 一键试还原 | 生成后直接点「试还原」，当场把噪声变回原图，不必先下载再切页 |
| 结果统计 | 展示改写像素比例等对比数据 |
| 复制图片 | 结果一键写进剪贴板，粘到聊天/文档不用先下载。写入前会主动抢一次焦点（嵌在预览面板里常见的 `Document is not focused` 靠这一步救回）；真被面板权限挡住时，提示按「下载 PNG」或「新窗口查看」→ 右键图片复制。**注意浏览器写剪贴板会重新编码**：实测（Chrome）像素逐字节不变，但 PNG 里的 `wbenc` 标记被剥、体积被重压缩。因此剪贴板版置乱图粘回本工具会提示「没有标记」，需补上备份串才能还原；而经聊天工具转发会被压缩像素，就彻底救不回了 |
| 粘贴提示 | 复制图片后直接 `⌘V`（拖放区上右键菜单没有「粘贴项」，这是浏览器限制）。剪贴板里放的是文件、图片地址或纯文字时，会明确说明为什么没反应，而不是静默失败 |
| 便捷输入 | 支持拖拽、点击选择、`⌘V` 直接粘贴图片 |
| 输入格式 | JPG / PNG / WebP / GIF / BMP，统一输出无损 PNG |

## 使用方法

1. 打开页面，把图片拖进唯一的入口（也可以点击选择，或 `⌘V` 粘贴）
2. 图进来后，页面会告诉你它像什么：是普通图片，还是本工具生成的置乱图
3. 点「打乱这张图」——动作区就在这张卡里往下展开，页面不跳转，缩略图和 ✕ 一直在上面
4. 按需调「打乱强度」（默认 100%）
5. 如需保密，填写口令；否则密钥会写进图片元数据，任何人都能还原
6. 点「生成置乱图」→「下载 PNG」。想立刻确认效果，直接点「试还原」，噪声会当场变回原图
7. 收到置乱图的人：拖进同一个入口 → 点「还原这张图」→ 开始还原

入口只有一个，动作由按钮决定。工具会提示这张图「像什么」，但**不会替你做决定**——被截图或压缩过的置乱图没有元数据，在没有元数据的情况下它和普通照片技术上无法区分，猜错比不猜更糟。

动作区展开后想换图，不必退出：点缩略图上的 **✕** 清空，或者**直接把新图拖进来 / 粘贴**——整张卡都是投放区，图会被替换、两边的结果一起清掉，避免拿错图的结果去下载。想收起动作区，点一下已经高亮的那个动作按钮即可；再点开还是原来的结果，不会重新算。

**务必保留 PNG 原文件，并且别用截图或「发图片」的方式转手。** 置乱图一旦被微信压缩、截图或转存为 JPG，像素就被改写了，**用任何方式都还原不回来**——包括加密时保存的那串字符。它只能救另一种情况：图片被无损重新保存、只是本工具的标记被剥掉了。

想保真地发给别人，请用**发送文件**（或打包成 zip），不要用发图片、不要截图。微信的「原图」也只是尽量保真，不保证像素不被改动。

## 原理

核心是两步互逆变换，两步都是「一一对应」，因此整体严格可逆。

```
    原图  ──① 位置置换──▶  ──② 逐像素异或──▶  噪声图
                                                    
    原图  ◀──① 逆向置换──  ◀──② 逐像素异或──  噪声图   （执行顺序相反）
```

1. **位置置换（Permutation）**
   用密钥派生的伪随机流做 3 轮随机交换，把每个像素搬到毫不相干的位置，彻底破坏空间结构。

2. **值置换（Keystream XOR）**
   每个像素的 R/G/B/A 再与密钥流派生的随机字节逐位异或，摧毁颜色分布、直方图与边缘统计。

3. **可逆性**
   交换的逆运算就是交换本身，异或的逆运算就是异或本身。加密与解密复用同一条密钥流，只是执行顺序相反。

### 关于「打乱强度」

强度决定有多少像素参与置换，参与密度取强度的平方：

- **低强度**：只有少量像素「搬家」，画面局部破碎但轮廓仍在，适合想要可见效果的场景
- **高强度**：几乎每个像素都参与，整幅图变成均匀噪声

关键设计：参与搬家的像素不限于相邻位置，它可以与**全图任意位置**的像素交换颜色。因此即使强度不满 100%，也**不存在成块原样保留的像素**——早期版本正是因为在低强度下留有成片未动像素，眼睛才能把它们拼回模糊的原图。

### 密钥派生

```
口令（可为空） + 随机盐
      │
      ▼  PBKDF2-HMAC-SHA256，20 万次迭代
      │
   32 字节主密钥  ──▶  派生出置换序列与异或密钥流
```

- 设置口令：密钥不随图保存，**没有口令无法还原**
- 留空口令：使用一次性随机密钥，并写入图片 PNG `tEXt` 元数据块，图片自身即可还原

### 怎么确认「真的解对了」

置乱是可逆的，但「算出结果」不等于「解对了」——拿一把合法钥匙去解一张不相干的图，程序照样会吐出一张图，只是满屏噪声。所以生成时会给原图算一个**像素指纹**并写进元数据：

```
指纹 = SHA-256( 密钥 ‖ 宽 ‖ 高 ‖ SHA-256(原图 RGBA 字节) )[0..8]
```

还原分两票判定：`t` 验证钥对不对，`f` 验证图对不对。两票都过才敢说成功。

- 指纹掺入密钥是必要的：裸哈希会让持图者拿一张候选原图算一遍，就能确认「这张噪声图原来是它」。
- 只有一张 46MB 像素的图要遍历一次，实测约 0.25 秒。

### 为什么输出必须是 PNG

JPG 是有损压缩，重新编码会改动密文的比特位，导致还原永久失配。本工具自行编码 PNG（8bit RGBA + 非压缩数据块），主动绕开浏览器 canvas 对半透明像素的预乘舍入误差，保证像素字节完全无损。

## 安全边界（重要）

- ✅ 能防「随手看一眼」：任何人看到的都只是噪声
- ✅ 设了口令后，没有口令连统计分析都无从下手
- ⚠️ **这不是经过密码学审计的加密方案**，请勿用于真正机密的资料
- ⚠️ 原图的 EXIF、ICC 等元数据在重新编码时会丢失，只有像素被完整保留
- ⚠️ 置乱图被压缩、截图、转 JPG 后像素即被改写，**不可逆地失效**；元数据备份也救不回来，只能找回原始 PNG

## 技术栈

- 单文件 HTML，内联 CSS + 原生 JavaScript，**零外部依赖、零构建步骤**
- 自带 SHA-256 / HMAC / PBKDF2 的纯 JS 实现
- 自带 PNG 编解码器（tEXt 元数据读写、CRC32 / Adler32、zlib store 模式）
- 全部计算在浏览器本地完成，**图片不会上传到任何服务器**
